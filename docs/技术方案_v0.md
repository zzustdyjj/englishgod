# Personal English Agent 技术方案 v0（骨架阶段）

> 状态：草案，待发起人确认。依据 `Personal_English_Agent_理念与需求说明.md` 及 2026-10-09 的问答整理。

## 1. 已确认的决策

| # | 决策 |
|---|---|
| 范围 | 搭通用核心（会话 → 提炼 GAP → 记录 → 复习），各学习路径作为“入口”接入。骨架只接截图入口。 |
| 用户 | 以后会给别人用：从第一天起按多用户设计，带账号登录。 |
| 完成标准 | 手机发截图 → 当场聊清 → 点“记录” → 生成带原图的 GAP → 列表可见、复习可翻卡。 |
| 最终目标 | 截图询问、文字对话、语音对话都能发现 GAP；可按单词 / 说 / 听 / 读等类别，用模板整理。 |
| 设备 | 手机为主，网页应用（PWA）适配手机。 |
| 部署 | 测试期电脑常开 + 内网穿透给手机用；以后用户可自部署、填自己的 API key，或使用官方托管。 |
| 语音 | 最终由 Agent 自己负责语音对话（实时语音模型）。 |
| 课程 | 以后再集成。 |
| 模型 | 不绑定厂商，每个用户自选模型、自填 key。 |
| 讲解 | 默认中文讲解、英文例句，原文词保留英文。AI 直接解释，不先让用户猜。 |
| 模板 | 内置通用模板，用户可选择或自定义；不依赖 OneNote。 |
| 记录时机 | 对话期间正常回答；用户觉得问清楚了，点“记录”，AI 把本次所有 GAP 提炼入库。 |
| GAP 结构 | 一个 GAP（表达锚点）挂多次“遇见”；用户出错的情景也作为遇见挂上（错误 + 情景 A、情景 B……）。 |
| 历史数据 | 不导入 OneNote。 |
| 复习 | 两种模式：① 按日期区间筛选 GAP，按模板导出；② 翻卡回忆，可标“已解决”，没想起来的会在下一轮再出现。 |

## 2. 核心数据模型

```text
User ─┬─ ModelConfig（用户自己的模型厂商、模型名、加密存储的 key）
      ├─ Conversation（source: screenshot | text | voice | course）
      │    └─ Message（role, text, 附件: 图片/音频, record_batch_id）
      │          └─ 点“记录” → RecordBatch（本次提炼覆盖的消息范围）
      ├─ Gap（表达锚点）
      │    ├─ anchor_text   如 "split the bill"
      │    ├─ kind          词 / 词块 / 表达 / 语法 / 发音 / 听辨 …（开放，不做封闭枚举）
      │    ├─ skills        读 / 听 / 说 / 写（可多选，用于按类别整理）
      │    ├─ core_note     弄清楚的核心结论
      │    ├─ status        active | solved
      │    └─ Occurrence（遇见，可多条）
      │         ├─ scene         情景描述 + 原图/原句/来源
      │         ├─ question      当时具体疑惑什么
      │         ├─ user_attempt  用户原话（如有）
      │         ├─ error         出了什么错（可空）
      │         ├─ clarified     这次弄清楚了什么
      │         ├─ evidence      已解释 / 提示下复述 / 独立说出 / 新场景用对
      │         └─ 指向 RecordBatch 与原始消息（可追溯完整对话）
      ├─ ReviewEvent（gap, 结果: 想起 / 没想起 / 标为已解决, 时间）
      └─ Template（内置或用户自定义；按类别选用）
```

要点：

- **原始对话永远保留**。GAP 是从对话提炼出来的“视图”，提炼规则以后改进时，可以重新跑。
- **同一表达再次遇见**：提炼时先按规范化文本检索已有 GAP，再让 AI 判断是否同一个；是则新增 Occurrence，否则新建 Gap。已解决的 GAP 再次出错时自动重新激活。
- 语音入口以后接入时，只是 Conversation 的 source 变成 voice、Message 附带音频，**后面的提炼、记录、复习全部复用**。

## 3. 系统结构

```text
手机/电脑浏览器（PWA）
   │  HTTPS（测试期：Cloudflare Tunnel 穿透到本机）
   ▼
后端 Python FastAPI
   ├─ auth        账号登录
   ├─ chat        会话与消息，调用模型回答（支持图片）
   ├─ extract     “记录”：提炼 GAP → 与已有 GAP 合并 → 入库
   ├─ review      列表筛选、翻卡队列、复习事件
   ├─ export      模板渲染导出
   └─ llm         模型适配层（LiteLLM，统一接多家厂商）
   │
   ├─ SQLite（测试期；以后可换 PostgreSQL）
   └─ 本地文件目录（图片、以后的音频）
```

| 层 | 选型 | 理由 |
|---|---|---|
| 后端 | Python 3.12 + FastAPI + SQLAlchemy | 发起人能读懂 Python；Agent 的核心逻辑（提示词、提炼、合并）都在这里 |
| 模型接入 | LiteLLM | 一套接口接 Claude、OpenAI、Gemini、DeepSeek、通义等，满足“用户自选模型” |
| 前端 | React + Vite + TypeScript，PWA，手机优先 | 以后做实时语音需要浏览器端能力（麦克风、WebRTC） |
| 存储 | SQLite + 本地文件 | 零运维；用户自部署也简单 |
| 测试期访问 | Cloudflare Tunnel | 免费，手机在外也能访问本机 |

## 4. 里程碑

| 阶段 | 内容 |
|---|---|
| M0 骨架 | 登录、模型配置、截图会话、点“记录”提炼 GAP、GAP 列表、翻卡复习、Markdown 导出 |
| M1 | 纯文字对话入口；按单词 / 说 / 听 / 读分类的内置模板；按日期导出 |
| M2 | 实时语音对话入口（保存音频与转写，复用提炼流程） |
| M3 | 课程入口（预读课程音频与文本） |

## 5. Demo 阶段的取舍（2026-10-09）

为了尽快验证想法，demo 相对上面的方案做了简化，验证后再补：

| 方案 | Demo |
|---|---|
| 多用户 + 登录 | 单用户，无登录，仅本地 / 局域网 |
| 用户在界面里自选模型和 key | 在 `.env` 中配置一个模型 |
| React 前端 | 原生 JS 单页，由后端直接提供，无需构建 |

按默认处理的决定：

- “按模板整理”在点“记录”时完成：AI 把 GAP 整理成结构化字段，复习和导出时模板只负责排版。
- 导出为独立 HTML（图片内嵌，可打印成 PDF）。内置“通用卡片”和“单词表格”两个模板。
- 翻卡时由用户自己判断“想起来了 / 没想起来 / 已解决”；没标“已解决”的 GAP 会继续留在队列里。
- 点“记录”后直接入库，事后可在 GAP 列表里标记或删除。
